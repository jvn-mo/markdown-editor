# Markdown 编辑器升级计划

## 一、升级目标与版本建议

将当前的基础 Markdown 编辑器升级为更稳定、离线可用、安全、适合日常写作与文档导出的桌面应用。

建议采用分阶段版本：

| 版本 | 主题 | 目标 |
|---|---|---|
| `v1.1` | 稳定性修复 | 消除数据丢失、导出、预览等高频问题 |
| `v1.2` | 编辑体验 | 提升写作、查找、预览、快捷操作体验 |
| `v1.3` | 场景适配 | 面向知识笔记、技术文档、办公导出等场景 |
| `v1.4` | 工程化与安全 | 完善安全、离线、测试、发布能力 |
| `v2.0` | 编辑器能力重构 | 使用专业编辑器内核，支持扩展能力 |

# 阶段 0：改造前准备

> 目标：在改动功能前，建立可回滚、可验证、可发布的工程基础。

## 0.1 建立版本控制

当前项目没有 Git 仓库，建议最先执行：

```bash
git init
git add .
git commit -m "chore: baseline before v1.1 upgrade"
```

补充 `.gitignore`，至少忽略：

```gitignore
node_modules/
dist/
*.log
.DS_Store
```

注意：如果 `dist/` 中的安装包有留存价值，应单独备份或通过 Releases 管理，而不是提交到 Git。

**验收标准：**

- 每项功能改动都有独立提交记录；
- 能通过 Git 回退至升级前版本；
- 构建产物不再混入源码版本库。

## 0.2 补齐开发规范与基础文档

新增或完善：

- `README.md`：功能、开发环境、启动、构建、发布方式；
- `CHANGELOG.md`：按版本记录用户可感知的改动；
- `.gitignore`；
- `CONTRIBUTING.md`（可选）：贡献和提交规范；
- `docs/known-issues.md`：已知问题与解决状态。

推荐加入：

- ESLint：检查 JavaScript 逻辑问题；
- Prettier：统一代码格式；
- `npm run lint`；
- `npm run test`；
- `npm run build`。

**验收标准：**

- 新成员可根据 README 成功运行项目；
- 每次发布都能写清楚“新增 / 修复 / 已知问题”；
- `npm test` 不再只是输出 `No tests yet`。

## 0.3 建立手工回归测试清单

在自动化测试完善前，每次发布前至少测试以下项目：

1. 新建、打开、保存、另存为；
2. 同时打开多个文件；
3. 修改后关闭标签页；
4. 修改后关闭软件；
5. 导出 PDF；
6. 导出 DOCX；
7. 打开含公式、表格、代码块、Mermaid、图片的文档；
8. 大文档编辑与预览；
9. 断网情况下启动与编辑；
10. 安装包安装、卸载、`.md` 文件双击打开。

建议准备一组 `fixtures/` 测试文档：

```text
fixtures/
├─ basic.md
├─ math.md
├─ mermaid.md
├─ tables.md
├─ images.md
├─ large-document.md
└─ unsafe-html.md
```

# 阶段 1：v1.1 稳定性与高频 Bug 修复

> 优先解决用户最容易遇到的：丢内容、导出失败、预览卡顿、离线不可用。

## 1.1 修复“保存全部后仍退出”的数据丢失风险

### 当前风险

退出应用时，若存在多个未保存标签，用户选择“保存”后：

- 某个标签的“另存为”对话框可能被取消；
- 某个文件可能保存失败；
- 当前逻辑仍可能认为全部已保存并关闭软件；
- 导致后续标签内容丢失。

### 改造方案

让保存操作返回明确状态：

```js
{
  success: boolean,
  canceled: boolean,
  path?: string,
  error?: string
}
```

关闭流程改为：

1. 收集所有未保存标签；
2. 按顺序保存；
3. 任意一个标签取消保存：终止退出；
4. 任意一个标签保存失败：终止退出并提示错误；
5. 仅全部成功后才允许关闭窗口。

**验收标准：**

- 多标签中任意一次取消“另存为”，应用不退出；
- 保存失败时不会关闭应用；
- 全部保存成功后正常退出。

## 1.2 修复 DOCX 导出并发与临时文件冲突

### 当前风险

所有 DOCX 导出都使用固定文件名：

```js
temp_export.md
```

连续导出、多个标签导出或重复点击时，可能相互覆盖，导致 DOCX 内容错乱。

### 改造方案

- 每次导出创建唯一临时目录；
- 使用随机文件名或 `fs.mkdtemp()`；
- 导出完成后在 `finally` 中清理临时目录；
- 禁止导出按钮重复触发，导出中显示状态；
- 使用 `execFile` 替代拼接 shell 命令的 `exec`。

**验收标准：**

- 连续导出两个不同文档，内容完全正确；
- 导出过程中重复点击不会产生冲突；
- Pandoc 未安装、路径异常、文件被占用时有可理解的报错；
- 临时目录不会长期残留大量文件。

## 1.3 修复预览异步竞争与大文档卡顿

### 当前风险

每次输入都会马上执行完整 Markdown、KaTeX、代码高亮和 Mermaid 渲染。快速输入或 Mermaid 渲染较慢时，旧任务可能后完成并覆盖新预览。

### 改造方案

1. 输入后增加 `200ms` 左右防抖；
2. 为每次渲染分配递增的 `renderId`；
3. 异步操作结束时，仅当 `renderId` 仍是最新值才更新页面；
4. Mermaid 内容没有变化时不重复渲染；
5. 大于一定长度（如 100KB）的文档降低预览更新频率；
6. 渲染期间显示轻量状态，如“正在更新预览”。

**验收标准：**

- 快速连续输入不会发生预览内容回退；
- 包含 Mermaid 的文档连续编辑时不闪烁；
- 打开大文档时界面不长时间无响应；
- 预览最终内容始终与编辑区一致。

## 1.4 修复撤销/重做的边界问题

### 当前风险

当前自定义历史记录保存的是整篇文本快照，并通过定时器延迟入栈。可能出现：

- 编辑后立即切换标签，历史记录写入错误标签；
- Tab 缩进、替换、粘贴等操作的历史行为不一致；
- 大文件下内存占用增加；
- 保存后撤销状态与“未保存”标记不完全对应。

### 改造方案

短期建议：

- 统一所有文本修改入口；
- 在标签切换、关闭时清理当前的输入延时任务；
- 用“保存时内容快照”判断 `isDirty`，而不是只将它单向设为 `true`；
- 撤销回到保存状态时，自动取消“未保存”标记。

中长期建议：

- v2.0 更换为 CodeMirror 6，由编辑器内核维护撤销重做。

**验收标准：**

- 输入、Tab 缩进、查找替换、撤销重做均可正确标记未保存状态；
- 切换标签后不污染其他标签历史；
- 撤销到最后保存状态后，未保存标记消失。

## 1.5 修复查找替换功能缺陷

### 建议修复项

- 搜索关键词变化时重置搜索位置；
- 无结果时提示“未找到”；
- 支持 `Shift + Enter` 查找上一个；
- 替换前确认当前选区；
- “全部替换”后显示替换数量；
- 查找面板打开后自动选中已有文本；
- `Esc` 始终可关闭面板并将焦点还给编辑器。

**验收标准：**

- 查找、上一项、下一项、替换、全部替换均符合预期；
- 无匹配内容时用户能收到明确提示；
- 不会因空文本、关键词变化或循环查找产生异常。

## 1.6 修复版本与用户文档不一致

目前应用版本为 `1.0.2`，用户说明中仍提到 `1.0.1` 安装包。

### 改造方案

- 版本号只在 `package.json` 中维护；
- 应用界面通过 `app.getVersion()` 显示；
- 发布前自动更新 `CHANGELOG.md`；
- 用户说明使用通用安装包命名，不写死旧版本号。

**验收标准：**

- 安装包名、应用内版本、更新日志版本一致；
- 用户文档不再指向过期版本。

# 阶段 2：v1.2 编辑与写作体验升级

> 目标：让用户愿意长期使用它写 Markdown，而非仅“粘贴后导出”。

## 2.1 优化布局与窗口体验

### 功能项

- 记住窗口大小与位置；
- 记住左右分栏比例；
- 记住编辑器与预览主题；
- 记住字体大小；
- 记住最近打开文件；
- 支持双击分隔线恢复 50:50；
- 支持一键“仅编辑 / 仅预览 / 双栏”模式；
- 小窗口下隐藏过长的快捷键提示，避免工具栏拥挤。

建议将用户偏好存储到：

```text
app.getPath('userData')/settings.json
```

**验收标准：**

- 重启后主题、字体、窗口大小、分栏比例保持不变；
- 窗口宽度较小时界面不会按钮重叠或文字溢出；
- 一键切换专注写作模式可用。

## 2.2 增强状态栏

将当前的“文件名 + 未保存 + 字数”扩展为：

- 文件编码（默认 UTF-8）；
- 行数、字符数、词数；
- 当前光标：行 / 列；
- 文件修改状态；
- 预览渲染状态；
- 当前主题或缩放比例；
- 点击状态栏项目可切换相关设置。

特别适合技术文档、论文、长文写作场景。

## 2.3 增加 Markdown 快捷编辑工具

在工具栏、右键菜单或快捷键中提供：

| 功能 | 建议快捷键 |
|---|---|
| 加粗 | `Ctrl + B` |
| 斜体 | `Ctrl + I` |
| 删除线 | `Ctrl + Shift + X` |
| 行内代码 | `Ctrl + \`` |
| 标题升级/降级 | `Ctrl + Alt + ↑ / ↓` |
| 无序列表 | `Ctrl + Shift + 8` |
| 有序列表 | `Ctrl + Shift + 7` |
| 引用块 | `Ctrl + Shift + >` |
| 插入链接 | `Ctrl + K` |
| 插入图片 | 菜单或拖拽 |
| 插入表格模板 | 工具栏菜单 |
| 插入代码块 | `Ctrl + Alt + C` |

实现原则：

- 有选中内容时包裹选中内容；
- 无选中内容时插入模板并将光标放在合适位置；
- 所有操作纳入统一撤销历史。

## 2.4 增加编辑器常用能力

当前 `<textarea>` 阶段可以先实现：

- 自动补全 Markdown 标记：`**`、````、`[]()`、`""`、`()`；
- Enter 自动延续列表、引用与任务列表；
- Shift+Tab 批量反缩进；
- 多行选中后 Tab 批量缩进；
- 拖入 `.md` 文件直接打开；
- 粘贴 URL 时自动转换为链接；
- 粘贴图片时询问是否保存到文档附件目录；
- 自动保存草稿和异常退出恢复。

## 2.5 自动保存与崩溃恢复

### 建议策略

区分“写入正式文件”和“保存恢复草稿”：

- 自动恢复草稿：用户停止输入 2–5 秒后保存；
- 正式文件自动保存：可在设置中开关；
- 未命名文件保存到恢复缓存；
- 启动时检测异常退出草稿，并提示恢复；
- 用户成功保存、关闭标签或主动丢弃后清理草稿。

建议保存位置：

```text
app.getPath('userData')/recovery/
```

**验收标准：**

- 强制结束应用后，重新启动可恢复内容；
- 用户关闭未保存标签并选择“不保存”时，不应再提示恢复；
- 草稿恢复不覆盖原始文件，需明确询问用户。

# 阶段 3：v1.3 多场景适配

> 目标：从“基础 Markdown 工具”扩展为“个人笔记、技术文档、办公交付”都能胜任的工具。

## 3.1 离线模式与资源本地化

### 当前问题

KaTeX、Mermaid、Marked、highlight.js 均通过 CDN 加载。断网时可能无法使用公式、图表、渲染与代码高亮。

### 改造方案

- 将运行时库改为 npm 依赖；
- 使用构建工具将它们打包进应用；
- PDF 导出引用本地 KaTeX CSS；
- 不再依赖外部 CDN；
- 发布前在断网环境回归测试。

**验收标准：**

- 断开网络后，Markdown、公式、图表、高亮、PDF 导出功能全部正常；
- 首次启动不依赖网络；
- 不产生外部 CDN 请求。

## 3.2 本地图片、附件和相对路径支持

### 使用场景

技术文档和知识笔记常常包含：

```md
![架构图](./images/architecture.png)
```

当前应用应确保编辑、预览、PDF、DOCX 对这些资源处理一致。

### 改造方案

- 以 Markdown 文件所在目录作为资源根目录；
- 正确解析相对图片路径；
- 支持粘贴或拖拽图片；
- 可选择复制图片到文档同级 `assets/` 或仅引用原文件；
- 导出 PDF 时嵌入或正确引用图片；
- DOCX 导出向 Pandoc 提供 `--resource-path`。

**验收标准：**

- 打开含相对路径图片的 `.md` 文件可正常预览；
- 导出的 PDF 与 DOCX 均包含图片；
- 文档移动后若资源目录同时移动，仍能正常显示。

## 3.3 完善 Markdown 与文档兼容性

建议补充支持：

- GitHub 风格任务列表；
- 删除线；
- 脚注；
- 定义列表；
- YAML Front Matter；
- HTML 注释；
- 链接标题与锚点跳转；
- 更完整的表格对齐；
- 数学公式错误定位；
- Mermaid 错误提示，而不是静默忽略；
- Mermaid 导出为 SVG/PNG。

对于 Mermaid，建议将错误显示在预览区，例如：

```text
Mermaid 图表语法错误：第 3 行附近……
```

而不是直接吞掉异常。

## 3.4 文档大纲与导航

新增左侧可折叠的大纲栏：

- 根据 `#` 标题自动生成；
- 点击标题跳到编辑区与预览区对应位置；
- 高亮当前阅读章节；
- 支持搜索标题；
- 支持折叠低级标题。

适用场景：

- 长篇笔记；
- 产品需求文档；
- 技术设计文档；
- 论文和报告。

## 3.5 模板与快捷新建

提供内置模板：

```text
templates/
├─ 空白文档
├─ 会议纪要
├─ 周报
├─ 技术方案
├─ 项目 README
├─ 问题复盘
├─ 学习笔记
├─ 论文笔记
└─ Mermaid 流程图
```

可扩展能力：

- 用户自定义模板目录；
- “从模板新建”菜单；
- 最近模板；
- 新建文件时自动填入 YAML 元数据。

## 3.6 导出能力增强

### PDF 导出

增加：

- 页边距选择；
- A4 / Letter 等纸张规格；
- 横向 / 纵向；
- 页眉、页脚、页码；
- 文档标题；
- 导出前预览；
- 打印支持；
- 强制分页标记，例如 `<!-- pagebreak -->`。

### DOCX 导出

增加：

- 检测 Pandoc 是否安装；
- 在设置页显示 Pandoc 路径和版本；
- 可以配置中文字体、正文字体、标题字体；
- 支持引用自定义 Pandoc `reference.docx`；
- 导出时保留图片、表格、公式；
- 可选导出格式：DOCX、HTML、纯文本。

# 阶段 4：v1.4 安全、工程化与发布质量

## 4.1 Markdown 内容净化

### 当前风险

Markdown 被渲染为 HTML 后直接写入 `innerHTML`。若文档来源不可信，可能被注入危险 HTML。

### 改造方案

- 引入 DOMPurify；
- HTML 插入预览前执行净化；
- 默认禁用 `script`、`iframe`、内联事件（如 `onclick`）及危险 URL 协议（如 `javascript:`）；
- 提供设置项：“允许原始 HTML”，但默认关闭；
- 外部链接在系统浏览器打开，不让页面自由创建新窗口。

**验收标准：**

- 打开含 `<script>`、`onerror`、`javascript:` 的 Markdown 不执行恶意代码；
- 正常的表格、公式、图片、链接不受影响。

## 4.2 强化 Electron 安全配置

建议增加：

- `sandbox: true`；
- 严格 Content Security Policy；
- 限制 `will-navigate`；
- 限制 `setWindowOpenHandler`；
- 严格校验 IPC 参数类型与长度；
- 所有文件读写仅允许经过用户选择或受控目录；
- 不将完整的 Electron/Node API 暴露给渲染进程。

## 4.3 更新依赖与构建链

目前完整 `npm audit` 报告的漏洞主要来自旧版 Electron 和 electron-builder 的开发/打包依赖链。

升级流程建议：

1. 升级 Electron 至当前稳定版；
2. 升级 electron-builder；
3. 更新锁文件；
4. 执行 `npm audit`；
5. 在干净环境执行 `npm ci`；
6. 执行完整构建；
7. 用安装包进行手工回归测试。

注意：不要直接依赖 `npm audit fix --force`，先在分支中升级并验证，因为 Electron 大版本升级可能有 API 兼容性问题。

## 4.4 引入自动化测试

### 单元测试

适合测试：

- 文件名与导出名生成；
- Markdown 相对资源路径解析；
- 数学公式占位保护；
- 查找替换；
- 标签状态、保存状态；
- 设置序列化和恢复；
- Pandoc 参数生成。

### 集成测试

适合测试：

- 创建 / 打开 / 保存文件；
- 多标签关闭与未保存提醒；
- PDF / DOCX 导出流程；

# 阶段 5：v2.0 编辑器内核升级

> 此阶段不建议在 v1.1 立即开始。应当先完成稳定性、离线、安全和测试基础建设。

## 5.1 从 textarea 迁移至 CodeMirror 6

建议优先选择 **CodeMirror 6**，而不是 Monaco：

| 项目 | CodeMirror 6 | Monaco Editor |
|---|---|---|
| 体积 | 更轻量 | 较大 |
| Markdown 场景 | 很合适 | 合适 |
| 扩展性 | 强 | 强 |
| 移动/低配设备 | 相对更友好 | 较重 |
| VS Code 风格 | 一般 | 很强 |

CodeMirror 6 可带来：

- Markdown 语法高亮；
- 行号；
- 当前行高亮；
- 代码折叠；
- 多光标；
- 强大的搜索替换；
- 统一撤销重做；
- 自动补全；
- 更稳定的大文档编辑体验；
- Vim / Emacs 键位扩展（可选）。

# 推荐的实际执行顺序

如果准备开始迭代，建议按以下顺序实施，避免边改边引入新问题：

1. **建立 Git、.gitignore、README、CHANGELOG、回归测试清单。**
2. **修复多标签保存退出的数据丢失风险。**
3. **修复 DOCX 导出的临时文件冲突、错误处理与导出中状态。**
4. **修复查找替换、撤销重做、未保存状态不准确等日常 Bug。**
5. **优化实时预览：防抖、异步竞争控制、Mermaid 错误显示。**
6. **实现设置持久化、自动草稿恢复、最近文件。**
7. **将在线 CDN 依赖改成本地打包，实现离线可用。**
8. **支持相对图片路径、粘贴图片、导出资源处理。**
9. **引入 DOMPurify、CSP 与 Electron 安全限制。**
10. **升级 Electron / electron-builder，清理依赖漏洞。**
11. **添加大纲、模板、打印和高级导出。**
12. **最后迁移 CodeMirror 6，并逐步采用 TypeScript。**
